# React DOM 17 to 18 consumer fixtures

Synthetic before/after consumer sources for the `react-dom-17-to-18` provider
recipe (see `docs/TRANSFORMER_FRAMEWORK_RECIPES.md`). No real customer code.

- `before/` — a React 17 consumer on the recipe's supported surface:
  `src/index.jsx` imports the default `react-dom` namespace and calls
  `ReactDOM.render(<App />, container)`, plus a `package.json` that declares the
  `react` and `react-dom` v17 dependencies. Analysis classifies this as
  `applicable`.
- `after/` — the exact deterministic output of applying the recipe to `before/`.
  The render call becomes `createRoot(container).render(<App />)`, the import
  becomes a used-symbol import from `react-dom/client`, and `react`/`react-dom`
  are bumped to v18. Regenerated by the transform and asserted byte-for-byte in
  `packages/transformer/src/recipe-react-dom.test.ts`, so it never drifts.
- `out-of-scope/` — a React 17 consumer that passes the removed third callback
  argument to `render`, which React 18 dropped and which has no deterministic
  single-expression mapping. Analysis classifies this as `unsupported` and the
  recipe abstains.

Files are pinned to LF (`.gitattributes`) so the content-addressed digests are
stable across platforms.
