# Warden P0 + P1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the public “Introducing Warden” narrative claim-safe (P0), then deliver the six demo capabilities as working product paths (P1).

**Architecture:** Keep Mendpoint’s existing loop — OpenAPI/SDK signals → change-intel → graph impact → generation/PR → policy → optional repair/Warden. P0 is mostly brand, docs, and one recorded partner path. P1 adds changelog intelligence, adopt economics, drift probe → Warden, multi-service PR grouping, and a small real-issue eval pack. Never auto-merge by default.

**Tech stack:** TypeScript monorepo `@mendpoint/*`, Hono API, Next.js web, SQLite (`@mendpoint/db`), Vitest, GitHub App/Octokit, worker CLI.

**Source of truth for gaps:** `docs/WARDEN_VISION_GAP_ANALYSIS.md` §7–8.

**Out of scope (P2+):** PR chat revise, cloud sandbox fleet, model router, cross-customer data moat, provider distribution channel, public SWE-bench publication.

---

## Success criteria

### P0 done when

1. Intro / README / product docs use **claim-safe** language (no RSS forever, no unprompted hunting, no $ savings, no published bench leadership).
2. Pipeline + Warden PRs/UI say **Warden** (or “Opened by Warden”) consistently.
3. A **design-partner path** doc + scriptable checklist exists: App install → monitor → feed poll → impact PR on a real or partner-like repo, with audit artifacts.
4. `npm test` green; no new auto-merge defaults.

### P1 done when

Each of the six demos has: (a) code path, (b) fixture or partner case, (c) test or recorded run, (d) one-line demo script or UI entry.

| Demo | Acceptance |
|------|------------|
| Breaking before prod | Changelog/release text or structured notes → surfaces + optional `deprecation_at` on change |
| Feature + savings | Adopt PR body includes simple quantified heuristic (even rough) |
| Silent drift | Probe job or CLI detects schema/type drift → enqueues Warden run |
| Multi-service PRs | One change can open/group ≥2 PRs or draft bundles by service ownership |
| Continuous changelog | Poller for RSS or GitHub Releases → relevance filter → optional pipeline |
| Real repo fixes | Eval pack of 5–10 redacted API-break issues; Warden or pipeline scores tracked |
